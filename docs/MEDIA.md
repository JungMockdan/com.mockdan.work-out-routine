# 시연 영상 (유튜브 큐레이션)

운동별 시연 영상을 유튜브에서 골라 앱에 붙이는 절차. 단일 진실 소스는
[`src/data/exercise-media.ts`](../src/data/exercise-media.ts)이고, 이 문서는 그 파일을 다루는 방법이다.

---

## 1. 핵심 규칙 4가지

**① 검수를 통과하지 않은 영상은 앱에 나오지 않는다.**
`exerciseVideos()`가 `reviewedBy`/`reviewedAt`이 없는 항목을 걸러낸다. 그래서 후보를 매니페스트에
넣어두는 것 자체는 안전하고, **매니페스트가 곧 리뷰 대기열**이 된다.

**② 영상 검수 ≠ 처방 검수.** SPEC 9장의 `exercises.reviewed_by`는 처방·금기의 타당성 문제다.
여기의 `reviewedBy`는 "이 영상이 이 운동의 올바른 시연인가"만 뜻한다. 하나를 채워도 다른 하나는 안 닫힌다.

**③ 영상은 `cues`를 대체하지 않는다.** `ExerciseCard`의 `showMedia` 기본값이 `showCues`에 묶여 있는 것은
의도다 — 큐가 꺼진 화면(온보딩 미리보기)에는 영상도 나오지 않는다. 자리를 만들려고 큐를 숨기지 말 것.

**④ 실행 화면(`/session/[date]`)에는 넣지 않는다.**
[`useWakeLock.ts`](../src/hooks/useWakeLock.ts)의 iOS 폴백이 무음 오디오를 `volume = 0.01`로
**재생 중**이다(`muted`가 아니다). 소리 있는 유튜브가 오디오 세션을 뺏으면 40분 세션 도중
화면 꺼짐 방지가 조용히 해제되고, 사용자는 원인을 알 수 없다.
광고가 루틴 중간에 돌아가는 문제와 레이아웃 초과는 그다음 이유다.

> 실행 화면에 시연이 필요하다면 그건 **소리 없는 3~6초 자체 호스팅 루프**여야 한다. 별개 과제다.

## 2. 왜 `Exercise.mediaRef`를 안 쓰는가

`plan-service.ts`가 `buildPlan()`을 호출하면 `Block.items[].exercise`에 `Exercise` 객체 **전체**가
들어가고, 그대로 `StoredSession.blocks` 스냅샷으로 동결된다(SPEC 4.3이 요구하는 불변성).

| `mediaRef`에 넣으면 | 매니페스트에 넣으면 |
|---|---|
| 이미 계획을 만든 사용자는 계획이 끝날 때까지 영상을 못 본다 (12주면 12주) | 다음 렌더부터 전원 반영 |
| 영상이 삭제·비공개로 바뀌어도 **이미 만들어진 계획의 죽은 링크를 고칠 수 없다** | 한 줄 고치면 끝 |
| `seed-exercises.ts`의 `media_ref` 쓰기는 런타임에 읽히지 않는 죽은 쓰기 | 해당 없음 |

`mediaRef`는 `engine.ts`(수정 금지)와 마이그레이션이 참조하므로 **null로 남긴다.**
`verify-media.ts`가 전부 null인지 트립와이어로 단정한다.

## 3. 작업 절차

### 3-1. 후보 검색 (Claude가 할 수 있는 부분)

한국어 우선, 없으면 영어. 병원·물리치료사·공공기관 채널을 우선한다.

```
검색어 예: "<nameKo> 방법 youtube",  "<nameEn> how to"
```

### 3-2. oEmbed로 검증하고 매니페스트에 기입

**제목·채널명을 손으로 옮겨 적지 말 것.** oEmbed 응답에서 그대로 가져와야
`--check-links`가 거짓 "제목 변경" 경고를 내지 않는다.

```bash
curl -s "https://www.youtube.com/oembed?url=https%3A//www.youtube.com/watch%3Fv%3D<VIDEO_ID>&format=json"
```

| 응답 | 뜻 |
|---|---|
| `200` + `{title, author_name}` | 살아있고 임베드 가능 |
| `400` | 잘못된 ID |
| `401` / `403` | 임베드 차단·접근 제한 → 쓰지 않는다 |
| `404` | 삭제·비공개 |

API 키가 필요 없다.

`reviewedBy`/`reviewedAt`은 **비워둔 채로** 기입한다. `note`에는 검수자가 무엇을 확인해야 하는지 적는다
(예: "여러 목운동 묶음 — 친 턱 구간을 찾아 `startSec` 지정 필요").

### 3-3. 사람이 검수 (Claude가 할 수 없는 부분)

Claude는 **영상을 볼 수 없다.** 검색·생존 확인·제목 기록까지가 한계고,
자세가 정확한지·그 운동이 맞는지는 판단하지 못한다.

검수 체크리스트:

- [ ] **이 운동이 맞는가.** 이름이 비슷한 다른 운동이 아닌지. (예: 흉근(pec) vs 흉추(thoracic))
- [ ] **모달리티가 맞는가.** 셀프 릴리즈인데 치료사가 해주는 도수치료 영상은 아닌지.
- [ ] 장비가 `equipment`와 맞는가 (볼/벽/머신…).
- [ ] 자세가 `cues`와 모순되지 않는가.
- [ ] 금기(`contraindications`) 대상자에게 위험한 변형을 권하지 않는가.
- [ ] 해당 동작이 영상 중간에 있으면 `startSec` 지정.
- [ ] 과도한 광고·인트로·판매 유도가 없는가.

통과하면 `reviewedBy`(`REVIEWERS` 멤버)와 `reviewedAt`(오늘 날짜)을 채운다.
탈락이면 **항목을 지운다.**

### 3-4. 검증

```bash
npm run verify:media                     # 오프라인: 게이트·매니페스트 무결성·커버리지
npm run verify:media -- --check-links    # + 유튜브 링크 생존 (200ms 간격, 1회 재시도)
npx playwright test e2e/media.spec.ts    # 게이트 차단 + 라이트박스 동작
```

## 4. 링크 로트 대응

유튜브 영상은 삭제·비공개·임베드 차단으로 바뀐다. 주기적으로:

```bash
npm run verify:media -- --check-links
```

- **FAIL**(삭제·차단) → 해당 항목을 지우고 대체 후보를 3-1부터 다시.
- **경고**(제목·채널명 변경) → 실패가 아니다. 채널명 변경은 흔하다.
  매니페스트의 `title`/`channel`을 새 값으로 갱신하면 경고가 사라진다.
  단 **제목이 전혀 다른 내용으로 바뀌었다면 재검수 대상**이다 — 영상이 교체됐을 수 있다.

운동당 후보를 2~3개 두는 이유가 이것이다. 하나가 죽어도 대체제가 있다.

## 5. 저작권

- **공식 iframe 임베드만 쓴다.** 유튜브 ToS가 허용하는 용도다.
- 다운로드·재호스팅 금지. 광고·브랜딩 제거 금지.
- **채널명을 카드에 반드시 표시한다** (`ExerciseVideos.tsx`가 렌더한다 — 지우지 말 것).
- iframe 호스트는 `www.youtube-nocookie.com`(프라이버시 강화 모드), 썸네일은 `i.ytimg.com`.
- `next.config.ts`에 CSP를 추가하게 되면 `frame-src`에 `https://www.youtube-nocookie.com`,
  `img-src`에 `https://i.ytimg.com`를 넣어야 한다.

**시사점**: 74종을 일괄 검색해 채우는 방식은 통하지 않는다.
`release`와 `integration` 페이즈는 명칭이 덜 표준화돼 있어 검색 정확도가 낮으므로,
영어 검색 병행 또는 일부는 직접 촬영을 고려해야 한다.
`strength`·`mobility`는 한국어 검색만으로 충분해 보인다.
